## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `Directory.Build.props` (`<Version>`) / `.release-please-manifest.json` | release-please bumps the version | take the **higher** |
| `CHANGELOG.md` | release-please appends | **union** |
| `README.md`, `docs/*.md` | parallel features document themselves | **union**, then rerun `MusicTheory.DocTests` |
| `MusicTheory.Guitar.UnitTests/Golden/*.txt` | derived output | **regenerate** (`UPDATE_GOLDEN=1`), review the diff |
| `MusicTheory.UnitTests/Reference/*.csv` | generated by music21 | **regenerate** (`tools/reference/generate.py`) |
| `MusicTheory/Chord.cs` (`ChordTypes`) | every chord feature adds rows | **union** the rows |
| Test files | both append tests | **union** |
- **Rule of thumb:** union additive files, regenerate derived files, take-the-higher for the version;
  same-logic-both-sides is a real semantic conflict — understand both intents or stop.

## Architecture grain / invariants (shape implementation plans to these)
- Spelled values (`Note`, `Interval`, `Chord`, `Scale`, `KeySignature`, `ChordSymbol`) are sealed records with value equality and constructor validation; build by interval from a root, never by semitone arithmetic.
- Never clamp or respell silently: `Note.Transpose` throws past two accidentals.
- One chord-type table (`ChordTypes` in `Chord.cs`); spoken names live in `MusicTheory.Guitar/VoicingDescriber.cs`.
- Coverage stays at 100%: delete an unreachable branch rather than test around it. Keep tables Stryker must mutate in methods, not `static readonly` initialisers.
- Docs examples are executed: every `Console.WriteLine` carries its expected output as a trailing `// comment`. Site samples are computed by SiteGen, never typed. No em dashes in visible copy.
- New import/export formats ship as separate packages (`MusicTheory.ChordPro`, `.Midi`, …), not in the core.
